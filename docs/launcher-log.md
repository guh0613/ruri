# 启动器日志与通知

“启动器日志”取代原下载页。日志、任务结果和通知共享 `LauncherJournal`，游戏的完整进程输出仍由现有运行记录管理，日志条目可以链接到对应会话。

## 记录事件

- 普通事件使用 `AppModel.report(message, level:sessionID:fileURL:)`，优先传入 `LocalizedMessage`。
- 长时间操作使用 `AppModel.perform`，进度通过 `progress(id, value)` 更新。任务只产生一条记录，任务内的 `report` 通过 TaskLocal 关联到它，结果和附件保存在同一条记录中。
- 与任务无关的后台事件独立记录；警告和错误进入“需关注”。顶层 `AppModel.error` 在保留错误提示框的同时写入日志。
- 重要消息与任务结果进入应用内通知收件箱。选中记录即标记已读，也支持全部标记已读。正常取消不产生未读通知，但需要检查恢复文件的取消结果仍会通知。
- 不记录访问令牌、请求正文或游戏的原始进程输出。持久化内容会过滤常见凭据，复制和导出还会隐藏用户主目录。

## 保存与保留

日志保存在启动器数据根目录的 `launcher-log.json`，不改变实例状态文件。写入在后台串行进行，通过原子替换保存；任务开始、结果、通知和已读状态立即排队保存，实时进度最多每五秒保存一次。退出前等待已排队的写入完成。

保留最近 500 条结束记录，运行中的任务不受清除历史影响。每个任务保留最近 60 个阶段，相同阶段的进度更新只修改计数。再次启动时，未写入结果的任务标记为中断，提醒检查实例状态。无法读取的历史文件保留原样，此次运行使用内存日志并显示保存状态。

“文件传输”是当前运行期间的实时网络视图，保留下载服务提供的最近记录。文件传输的细粒度进度不作为单独通知；跨重启的结果通过所属任务保留。

## 验证

运行 `scripts/swift-build.sh test --filter LauncherJournalTests` 验证任务生命周期、通知去重、取消与恢复、记录上限、持久化及凭据过滤。`scripts/build-app.sh debug` 构建可运行的 macOS 应用。
